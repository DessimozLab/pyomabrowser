Download and access OMA data

Use this page if you want to download OMA results, export data from the browser, or access OMA programmatically.

OMA data can be accessed in several ways. The best option depends on how much data you need and whether you want to work manually, in a script, or through a large-scale pipeline.

Which access method should I use?

I want to... Use this
Download the results shown in a browser table Table download

Download data from browser tables

Many tables in the OMA Browser can be downloaded directly.

This is useful when you want a focused dataset, such as:

  • orthologs of one gene
  • members of one HOG
  • genes in one genome
  • HOGs in one ancestral genome
  • filtered results for a selected species or taxonomic range

To download a table, first apply any filters you need, then click the download icon at the upper right of the table.

Available formats may include:

  • CSV
  • TXT
  • JSON
  • XML
  • SQL
  • Excel

The exported file reflects the filters currently applied to the table.

Download the current OMA release

The full OMA database is available from the Downloads → Current release page.

Use bulk downloads when you need release-wide data for large-scale analyses, reproducible workflows, or local processing.

The current release page includes several categories of files.

Orthology relationships

Use these files to download orthology relationships from OMA.

Depending on the file, orthology relationships may be available:

  • by pairwise orthologs
  • by HOGs
  • by Strict Orthologous Groups
  • in text format
  • in OrthoXML format

Species phylogenies of HOGs may also be available in formats such as PhyloXML or Newick.

Sequences

Use sequence files when you need protein or coding DNA sequences for OMA entries.

OMA sequence downloads may include:

  • protein sequences
  • coding DNA sequences
  • sequence files split by domain of life
  • protein annotations

OMA identifiers are used to link sequences to OMA entries and other OMA data files.

Identifier mapping

Identifier mapping files connect OMA identifiers to identifiers from other resources.

Mappings may include links to:

  • UniProt
  • RefSeq
  • EntrezGene
  • Ensembl or other source database identifiers, depending on the genome source

Some mappings are based on exact sequence matches. Others come from the source genome files.

OMAmer database files

OMAmer database files are available for users who want to map protein sequences to OMA HOGs locally.

These are database files, not software. The OMAmer software itself is listed under Software.

Other files

The current release page may also include additional files such as:

  • species information
  • taxon IDs
  • scientific names
  • genome sources
  • group descriptions
  • close or similar OMA Groups
  • RDF or HDF5 files, depending on the release

Use archives for previous releases

Use Downloads → Archives if you need data from a previous OMA release.

Archives are useful for reproducibility, especially if you want to rerun or compare analyses based on a specific historical version of OMA.

When publishing analyses based on OMA, record the OMA release version and download date.

Download orthologs between two genomes

Use the Genome Pair Orthology tool when you want all predicted orthologs between two selected genomes.

The result is returned as a tab-separated file. Each line corresponds to one orthology relationship and may include:

  • first OMA gene ID
  • second OMA gene ID
  • orthology relation type, such as 1:1, 1:many, many:1, or many:many
  • associated group information, when available

This is the best option if your question is specifically: "Which orthologs are inferred between these two genomes?"

Export all-against-all data

The all-against-all export lets you export precomputed sequence comparison data for selected species in OMA.

This is mainly useful for advanced workflows, especially when combining user data with precomputed OMA data or running local orthology inference workflows.

Use this only if you specifically need all-against-all comparison files. For most users, pairwise ortholog downloads, HOG files, or the REST API will be more appropriate.

Access OMA through the REST API

The OMA REST API provides programmatic access to many of the same types of data available through the OMA Browser.

Use the REST API when you want to:

    • automate queries
    • retrieve orthologs for many genes
    • access HOG or genome information from scripts
    • build a tool using OMA data
    • avoid manual downloads from the browser

The REST API documentation describes available endpoints and parameters and includes live examples.

For developer-focused examples, see Developer resources.

Access OMA through Python or R

OMA provides wrappers for users who want to access OMA data directly in Python or R.

Use these if you prefer working in a scripting environment rather than calling the REST API directly.

Python access

The Python package provides access to OMA data through objects that can be used with common Python workflows.

It supports table-like data and can integrate with packages for downstream analysis, such as tools for HOG analysis, tree handling, and GO enrichment.

R access

The R/Bioconductor package provides functions to import OMA data into R objects.

It is useful for downstream analyses in R, including sequence analysis, phylogenetic analysis, GO enrichment, and genomic interval workflows.

For installation details and code examples, see Developer resources.

Use SPARQL for semantic queries

OMA also provides a SPARQL endpoint for querying OMA RDF data.

Use SPARQL when you need to:

  • run complex structured queries
  • combine OMA with other RDF resources
  • query orthology data using the Orthology Ontology
  • perform federated queries across resources

SPARQL is powerful but less beginner-friendly than the browser, downloads, or REST API. It is best suited for users already familiar with RDF or semantic web technologies.

For examples and technical documentation, see Developer resources.

Choosing between browser, downloads, API, and SPARQL

Use the browser when you want to inspect or download a small, focused result.

Use bulk downloads when you need many files from a full OMA release.

Use the REST API when you want to automate standard OMA queries.

Use Python or R packages when you want programmatic access in an analysis environment.

Use SPARQL when you need semantic queries, federated queries, or RDF-based integration.

Common pitfalls

I downloaded a table but it does not contain all OMA data

Browser table downloads export the data shown in that table, usually with current filters applied. Use bulk downloads for release-wide data.

My downloaded table is missing rows

Check whether filters are active. Table downloads usually preserve filters such as taxon, relation type, or evidence type.

I need data from an older analysis

Use the OMA Archives and match the release used in the original analysis. Results can differ between OMA releases as genomes and annotations are updated.

I want all orthologs between two species

Use the Genome Pair Orthology tool, not the ortholog table for a single gene.

I want all data for many species

Use bulk downloads or programmatic access. Browser tables are better for smaller, focused datasets.

I want to use OMAmer locally

Download the OMAmer database files from Downloads, and install the OMAmer software from the Software page.

REST API and SPARQL are not the same thing

The REST API is usually better for standard programmatic access. SPARQL is better for complex semantic queries and RDF-based integration.
