Run OMA on your own data

Use this page if you have your own protein sequences, proteomes, transcriptomes, or genome annotations and want to analyse them with OMA-related tools.

OMA provides several routes for working with custom data. You do not always need to run a full orthology inference pipeline. The best tool depends on your question.

Which tool should I use?

I want to... Use this
Infer orthologs and HOGs from my own set of proteomes FastOMA
Map new protein sequences to existing OMA HOGs OMAmer
Assess the quality of a proteome annotation OMArk
Compare my data to precomputed OMA data OMAmer or FastOMA, depending on the task
Run the older standalone OMA workflow OMA Standalone legacy
Analyse HOGs programmatically after inference pyHam

When should I run a full orthology inference?

Run a full orthology inference if you have a set of proteomes and want to infer orthologs, HOGs, or gene family evolution among those species.

Use FastOMA for new analyses.

You may not need full orthology inference if your goal is simply to:

  • assign protein sequences to existing OMA HOGs;
  • predict functional annotations from OMA mappings;
  • check whether a proteome annotation is complete;
  • compare a new proteome to the OMA database.

For those cases, OMAmer or OMArk may be more appropriate and faster.

FastOMA

FastOMA infers orthologs and HOGs from custom protein datasets.

Use FastOMA if you want to analyse your own genomes or proteomes rather than only browsing precomputed OMA Browser results.

FastOMA is appropriate when you want to:

  • infer orthologs among a custom set of species;
  • build HOGs for your own dataset;
  • run comparative genomics analyses on newly sequenced genomes;
  • analyse gene family evolution outside the current OMA release;
  • generate orthology results for downstream tools and workflows.

For installation, command-line options, example datasets, and troubleshooting, use the FastOMA GitHub repository and documentation.

OMAmer

OMAmer maps protein sequences to OMA HOGs.

Use OMAmer if you have new protein sequences and want to place them into the existing OMA framework without running a full orthology inference pipeline.

OMAmer is appropriate when you want to:

  • map proteins from a new genome to existing OMA HOGs;
  • assign sequences to known gene families;
  • transfer information from OMA to new data;
  • process large protein datasets quickly;
  • use OMAmer database files locally.

OMAmer relies on precomputed OMAmer database files, which are available from the OMA Downloads section. The OMAmer software itself is listed under Software.

OMArk

OMArk assesses the quality and completeness of proteome annotations using OMA HOGs.

Use OMArk if you want to evaluate a predicted proteome before running downstream comparative genomics analyses.

OMArk can help identify issues such as:

  • missing genes;
  • fragmented annotations;
  • contamination;
  • unexpected duplication patterns;
  • taxonomic inconsistency;
  • possible annotation problems.

This is especially useful before running FastOMA or interpreting gene family evolution, because incomplete or fragmented proteomes can affect orthology inference.

OMA Standalone (legacy)

OMA Standalone is the legacy standalone implementation of OMA orthology inference.

For most new analyses, FastOMA is recommended.

OMA Standalone takes coding sequences from genomes or transcriptomes in FASTA format. Amino acid sequences are the recommended input type, although nucleotide sequences are also supported.

With amino acid sequences, users can combine their own data with publicly available genomes from the OMA database. Precomputed all-against-all sequence comparisons can also be exported from the OMA website to reduce the most computationally intensive step.

Use OMA Standalone only if you specifically need the older workflow or need to reproduce analyses that used it.

Input requirements

For most OMA-related workflows using custom data, start from protein sequences in FASTA format.

Recommended input:

  • one protein FASTA file per species or proteome;
  • stable and unique sequence identifiers;
  • one representative protein per locus, when possible;
  • meaningful species names or species codes;
  • good-quality proteome annotations.

Before running large analyses, check that your input files do not contain:

  • duplicate sequence identifiers;
  • extremely short or fragmented proteins;
  • many alternative isoforms from the same locus, unless the tool supports them;
  • contaminant sequences;
  • inconsistent species naming;
  • unexpected stop codons or invalid characters.

For proteome quality assessment, run OMArk before large-scale orthology inference.

Working with isoforms

OMA generally represents genomes using one protein sequence per locus for orthology inference.

If your input proteome contains multiple isoforms per gene, consider selecting one representative isoform before running an orthology inference workflow.

Including many isoforms can inflate apparent duplications and complicate interpretation of HOGs, gene family size, and duplication/loss patterns.

Outputs

The outputs depend on the tool.

FastOMA outputs

FastOMA outputs may include orthology relationships, HOGs, and files for downstream comparative genomics analysis. The exact files depend on the run configuration.

Use these outputs when you want to analyse:

  • orthologous relationships;
  • gene family membership;
  • HOGs across taxonomic levels;
  • gene duplication and loss patterns;
  • downstream comparative genomics workflows.

OMAmer outputs

OMAmer returns mappings between input protein sequences and OMA HOGs.

Use these outputs when you want to:

  • assign custom sequences to OMA gene families;
  • connect new proteins to existing OMA annotations;
  • perform fast functional or comparative mapping;
  • prepare input for downstream tools.

OMArk outputs

OMArk reports proteome quality metrics based on expected gene content from OMA HOGs.

Use these outputs to detect potential problems before interpreting comparative genomics results.

Combining custom data with OMA data

Some workflows allow users to combine custom data with precomputed data from the OMA database.

For example, precomputed all-against-all files can reduce the computational cost of some workflows involving OMA Standalone. OMAmer also uses precomputed OMAmer database files to map new sequences to existing OMA HOGs.

Use this route when you want to compare new data with species already present in OMA, rather than running everything from scratch.

Recommended workflow

For a new proteome or set of proteomes:

  1. Prepare one protein FASTA file per species.
  2. Remove duplicate IDs and decide how to handle isoforms.
  3. Run OMArk to assess proteome quality.
  4. If you only need mapping to existing OMA HOGs, run OMAmer.
  5. If you need new orthology inference among your proteomes, run FastOMA.
  6. Use downstream tools such as pyHam, HOG viewers, or comparative genomics workflows to analyse the results.

Common pitfalls

I only have one proteome

If you only have one proteome, you probably do not need full orthology inference. Use OMAmer to map proteins to existing OMA HOGs, or OMArk to assess proteome quality.

My species is not in OMA

Use OMAmer to map its proteins to existing OMA HOGs, or use FastOMA if you want to infer orthology relationships among your own set of species.

My proteome has many isoforms

Decide whether to keep all isoforms or select representative isoforms. For many orthology workflows, one representative protein per locus is easier to interpret.

My results show many duplications

Check whether the input contains multiple isoforms, fragmented annotations, or duplicated sequence identifiers. Also consider running OMArk to assess annotation quality.

My expected gene family is missing

Possible explanations include incomplete annotation, divergent sequences, missing species in the reference database, or orthology inference limits. Check sequence quality and consider alternative search methods.

I want to reproduce an old OMA Standalone workflow

Use OMA Standalone legacy and record the software version, input files, OMA release, and any exported precomputed files.

I am not sure whether to use FastOMA or OMAmer

Use OMAmer if you want to place sequences into existing OMA HOGs. Use FastOMA if you want to infer new orthology relationships and HOGs among your own set of proteomes.
